# Designed experiments: from hunches to a reproducible search

## Starting point

The repository was README-only at session start, so there was no in-repository historical holdout winner or parameter ledger to inherit. The public project pages supplied in the brief report diverse past attempts: feature-family/model changes, magnetic/gravity/strain/topographic methods, thresholding and emitted-mass changes (including top-k/dotted densities), catalogue buffers, DEM/thermal/geochemical additions, and alternate output conventions. Those owner-maintained reports are used as priors; they do not provide an authenticated, complete configuration matrix.

This experiment isolates one geological question (H35-01): **does magnetic-contact persistence across upward-continuation scales add spatial holdout value beyond a single-scale `tmi_hg` ranking?** The detector family is therefore fixed to a deterministic Poisson-continuation transform for this batch. We do not mix in a U-Net/HGB architecture change, because that would confound the geophysical hypothesis with model capacity. Architecture remains a later, separately designed factor; it is not retired as “understood.”

The numeric ranges are design bounds for an experiment, not empirical optima. The spatial support scale is stated in metres because the competition grid is 100 m. The upper continuation range is limited to ten cells so the experiment does not silently become a regional background model.

### Organizer clarification changed the initial plan

The first local screening pass was run with a 0–3 cell catalogue-buffer factor, based only on older owner-maintained experimentation. Before exporting a candidate, review of DrivenData staff's September 21 clarification showed this was the wrong submission rule: the score masks known-catalogue pixels exactly, applies the 300 m penalty to nearby predictions normally, and new-fault pixels may lie within 300 m of a known trace. That first pass and its result are **invalidated**, not candidate evidence. The revised v2 design removes this buffer factor, fixes output masking to exact known pixels, and has been rerun as `reports/h35-01-20261004T164802Z-e58e5dbee6.json`; only that report and its separately validated TIFF are current. The NW proxy delta happens to be numerically +0.0103 in both records, but the earlier run cannot justify the final artifact or be used as independent confirmation. A later code review also removed a no-op “visible-label collar” from the scoring path: it was disjoint from every evaluation core and had no metric effect. The selected configuration was re-evaluated with the simplified split code, and all inner/NW DTI values matched within 1e-12. Official manual-review link: [Forum topic 11516, post 4](https://community.drivendata.org/t/scoring-clarification-are-known-usgs-ingenious-faults-masked-when-scoring-and-are-they-in-the-final-round-label-set/11516/4). Staff additionally define a “new fault” as any fault pixel not already captured by USGS/INGENIOUS, including newly mapped geometry of an existing fault system ([topic 11536, post 2](https://community.drivendata.org/t/where-do-you-draw-the-line/11536/2)).

## LHS design and selection protocol

`configs/h35-01-lhs.json` declares the sample count, seed, continuous bounds, categorical levels, and frozen factors. `src/gemsdoe35/design.py` draws eight candidates using an independently randomized permutation of eight equal-probability strata for **each numeric factor**; the one categorical magnetic-source factor is balanced and shuffled (three, three, and two rows). Candidate IDs are SHA-256-derived from canonical parameter JSON, not hand-assigned names. Tests check the stratum property, determinism, category balance, fixed-factor hashing, and uniqueness.

**Audit correction:** the original H35-01 runner passed only three fixed values (`catalogue_mask`, detector, and continuation levels) to the sampler. The saved H35-01 report stores the full split and protocol in its JSON, but its short configuration ID does **not** hash every fixed value. Do not treat that older ID as a complete protocol fingerprint. The runner now passes all registered fixed factors into the hash; the preregistered H35-02 design does so from its first run. Existing H35-01 evidence and its TIFF are preserved rather than silently renamed.

Important statistical limitation: an LHS guarantees univariate stratification (and the balanced category counts specified here). It does **not** guarantee pairwise/interaction coverage, a space-filling maximin distance, or a lower variance for every response function. The original McKay–Beckman–Conover result gives a variance advantage under its stated sampling/response conditions; it is not a universal guarantee that distinct configurations are distinct scientific ideas. Follow-up batches should use an interaction-aware design (e.g. maximin LHS or a sequential design) if the observed response shows important interactions.

Selection proceeds in two stages:

1. The eight feature-only candidates are compared on three contiguous development quadrants (NE, SW, SE); no model is fit and no labels are used to build the ranking surface. The 30-pixel margin erodes each quadrant boundary to keep evaluation cores spatially distinct. Candidate emission is compared with a single-scale `tmi_hg` baseline at matched mass.
2. The configuration with the best mean development-fold DTI delta is frozen and evaluated once on the reserved contiguous NW quadrant. The NW labels are not read during selection and do not determine the emission threshold or any mask.

The local gate is intentionally strict: all three development deltas and the reserved NW delta must be positive. A failure yields **no submission TIFF**. Even a pass is only a proxy screen: these labels describe existing public faults, while the competition's initial private set contains newly identified faults. There is no organizer-score claim and no submission slot is consumed by this code.

## H35-02 challenger: strain-field discontinuities

The fresh H35-02 batch in [`configs/h35-02-lhs.json`](../configs/h35-02-lhs.json) varies three numeric factors (`max_smoothing_sigma_m`, `min_orientation_coherence`, and `prediction_fraction`) and one balanced four-level categorical factor (`strain_source`). Eight LHS rows place exactly one point in every stratum of each numeric dimension and two rows in each strain-source category. The detector, number of scales, exact catalogue mask, current incumbent, spatial split, margin, metric radius, and holdout-reuse status are fixed and hashed with every configuration.

The candidate family computes scale-smoothed spatial derivatives of the provided geodetic second invariant, shear rate, and dilatation rate, combines gradient strength with 180-degree orientation coherence across scales, and ranks the most coherent discontinuities. It does not simply rank high strain magnitudes. This tests one hypothesis; it is not a trained probability model or proof that a strain edge is a fault.

**Observed screen, 2026-10-04 UTC:** the LHS-selected setting was dilatation rate, maximum smoothing sigma 542.46 m, orientation threshold 0.683, and 1.198% emitted mass. Its three development deltas versus matched-mass `tmi_hg` averaged +0.018067 DTI, but only two of three were positive (NE +0.013454, SW +0.041093, SE −0.000347). On NW it scored 0.016990 versus 0.019426 for `tmi_hg` (Δ −0.002436). The corrected comparison rescored H35-01 at the selected H35-02 fraction (1.1976%): H35-01 DTI was 0.030867 versus H35-02 at 0.016990, **both on exactly 27,979 NW pixels** (Δ −0.013877). H35-01's original 0.026904 was at 23,427 NW pixels and is not a fair comparator here. The H35-02 screen failed the predeclared gate; **no H35-02 TIFF was emitted, and no weekly slot was used**. Corrected machine record: [`reports/h35-02-20261004T180550Z-6882a35675.json`](../reports/h35-02-20261004T180550Z-6882a35675.json), [site-visible copy](evidence/h35-02-latest.json). The earlier `175239Z` report is retained as an archive but superseded because its incumbent mass was unequal.

The NW block had already been examined for H35-01, so this is a paired challenger screen on a reused block, not independent confirmation. Its negative result is still useful as a falsification of this selected strain-edge configuration under the stated proxy; it does not prove all strain-boundary variants unhelpful. Do not keep retuning against NW. Any future confirmation must preregister new outer geography or a multi-fold nested design.

## Parameter retirement rule

A factor is not “retired” because its current range happened to have no winner. It may be removed from future designs only after a replicated, spatially blocked estimate of its main effect is stable across the preregistered range, with uncertainty and interaction checks recorded. Failed or non-identifiable factors remain in the ledger as unresolved. The generated design and holdout report are stored under `reports/` so later sessions read evidence instead of re-naming configurations.
