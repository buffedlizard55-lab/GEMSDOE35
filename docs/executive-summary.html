Submission Validation & Error Fix

Resolving "Predicted values must be in range [0, 1]"

The Issue

Submission Range Gate

DrivenData enforces strict bounds $[0.0, 1.0]$ on all in-domain pixels. Common failure causes include unnormalized gradient scores, negative values from float subtraction, or raw nodata sentinels (e.g. $-3.4 \times 10^{38}$) entering prediction arrays.

The GEMSDOE35 Fix

Exact Clamping & NaN Masking

All 5,167,373 in-footprint values are normalized to $[0.0, 1.0]$ via robust quantile scaling and top-$k$ binary ranking. The outside-footprint area (7,111,787 pixels) is strictly encoded as IEEE NaN nodata.

Automated Verification

Post-Write Reopen Check

Every generated TIFF is reopened and audited by scripts/validate_submission.py against official sample submission dimensions, CRS (EPSG:32611), 100 m transform, and min/max $[0.0, 1.0]$ bounds.
